# 北单比分预测 Skill

## 铁律（不可违反）

0. **预测基于当前实际情况，历史数据仅作参考（2026-08-11用户核心要求）**。每一场预测只看**这场现在**的事实：双方当前伤病/停赛/轮换、开赛天气、双方近期（近5-8场）真实状态、本场战意形势。**禁止把历史统计（往年1:1率、跨年池、历史比分分布等）套进当前场次作为预测依据**——历史顶多帮助了解联赛风格/球队底蕴，决定比分的是本场实际情况。历史数据算出来的任何"率"都不是预测。
1. **SP辅助预测，不追高SP（2026-08-14用户澄清，纠正此前误执行）**。比分推导以当前实际情报为主；SP是辅助预测信息，不是禁区：
   - **不追高SP**：不因为某个比分SP高就去搏它（"梦幻场"概念不存在）；SP高低不单独决定选哪个比分
   - **SP辅助用法**：①官方25个比分的SP去水后=市场集体概率判断，作为先验校准我的推导（若我给的比分SP极低/极高，检查推导是否漏了信息）；②SP反映实力差与共识，与情报推导交叉验证；③SP变动流向作风险提示（一致增强信心，分歧标记风险）
   - **反例教训（2026-08-14）**：把"不追高SP"误执行成"完全不看SP"，54场11.1%≈瞎猜，A级17场仅1中。市场信息是全投注者的集体判断，扔掉它等于自废最强先验
2. **SP不主导决策**：不用于过滤选场、不用于排序、不单独决定比分（不追高）。SP作辅助：先验校准、交叉验证、风险提示。任何情况下比分的主推导来自当前实际情报，SP只修正不主导。
3. **不凑数**。今天没把握就是0场，绝不为了"每天给几场"硬选。
4. **防数据泄漏**：预测只能用赛前可获取的信息。赛季更替（8月初）时，上赛季末期数据打折；优先用最近1个月同一赛季节奏内的数据。
5. **每场冻结快照**：预测时记录 时间戳 + 所用数据截止日 + 双方近期画面 + 预测理由，存档。赛后不得改口。
6. **赛前情报强制收集（2026-08-11用户要求，不可跳过）**：每场预测前必须先收集双方所有影响条件——球员伤病/停赛/轮换、天气（温度/降水/风速）、球场等。这是必备步骤不是加分项。情报缺失时在预测快照里标注"情报缺口"，不得假装不存在。
7. **主动自检（2026-08-13用户要求，不等用户催）**：每次预测、复盘、改脚本后，**主动跑 `python3 self_check.py [期号]`** 出体检报告，发现 ❌ 立即修、发现 📌 记入待办，然后主动汇报"发现X个问题、已修/待办"。**不许等用户说"优化一下"才检查**——系统会生锈，主动自检是常态动作，不是被动响应。同时每满20条消息主动做一次覆盖式会话总结写入记忆。
7. **信号样本分级（2026-08-13用户要求，防自我污染）**：skill 里每条"规律/铁律/信号"必须标注其**依据的实战样本数 n**。分级：
   - **n ≥ 30**（或有 walk-forward 回测支撑）→ 可称"铁律/规律"
   - **5 ≤ n < 30** → 只能称"假设"，用"倾向/可能"措辞，禁止断言
   - **n < 5** → 只能称"单场观察"，只作参考，**不得作为下注依据**，除非有独立逻辑（如"门将伤→防守隐患"这种因果，而非"上次这样中了"这种巧合）
   - **判据**：任何从"某一场命中了"反推出来的规律，一律是单场观察，不是规律。防止把运气总结成经验、再拿经验害下期（精选线0/5就是教训）。

## 固定权重模型（不每期换标准）

单场预测按以下固定权重综合（合计100%）：

| 维度 | 权重 | 内容 |
|---|---|---|
| 近期画面（双向） | 30% | **必须同时分析主队和客队双方**：主队近期进攻画面 vs 客队防守漏洞、客队近期进攻画面 vs 主队防守漏洞，双方各自最近1个月的比分、进球数、丢球数、状态趋势（上升/下滑） |
| **球队进球属性** | 20% | **看分布不看平均**：查近8场里有多少场≥3球。≥5场=大球属性队，≤3场=小球属性队。双方都大球→这场大概率大球；双方都闷→小球。禁止用"场均2.0"判断闷 |
| **对位交锋** | 10% | **查双方近期交锋**：若最近交手是大球（如莫斯vs奥德踢过3:2），这是本场比分最强参考。若最近交手是1:0/0:0，则倾向小球 |
| 实力差/联赛定位 | 10% | 球队档次、联赛级别差、豪门vs保级/升班马 |
| 赛事类型 | 10% | 联赛/杯赛/资格赛——杯赛闷、南美低比分、欧战资格赛易爆冷 |
| 特殊因素 | 10% | 伤停、轮换、两回合背景、新赛季换帅、杯赛战意 |

**双向分析铁律：每一场都必须先分别回答"主队状态如何""客队状态如何"，再合起来判断比赛性格。禁止只看一方就下结论——只看主场屠杀就喊3:0、只看客队弱就喊2:0，都是偷懒。**

**进球机制铁律：禁止用"近5场场均"判断比赛性质。必须统计近8场里≥3球场次占比（大球属性），并查双方近期交锋比分。两队都大球+近期交锋大球 → 这场比赛就是大球，给2:2/3:1/3:2，不许缩成1:1。**

**进球属性判定表（三天复盘验证）：**
| 双方属性 | 判定 | 该给比分 |
|---|---|---|
| 一方≥60%大球 vs 一方≤40% | 单边型 | 2:0、2:1，**别贪3:0**（马尔默3:0→1:2、布拉格斯拉维亚3:0→2:1均证伪） |
| 双方都≥60%大球 | 大球倾向 | 2:2/3:1/3:2；**但接受偶发小球**（斯托姆加斯特75%vs埃格尔松75%→0:2） |
| 双方都≤40% | 小球 | 1:0/0:0/1:1 |

**三条反直觉规律（三天复盘沉淀，不可违反）：**
1. **交锋旧账最不可信**：沙姆洛克"交锋5次1:0"→实际3:2、阿尔特阿赫"交锋连平"→实际3:1。历史交锋是过去，**现在的大球属性才是当下**。禁止用旧交锋押低比分。
2. **禁止把大球属性队当"哑火"**：邓多克62%、WSG 75%、维塞乌62%都是大球属性，我当哑火处理导致给分太小。查属性后发现对手大球→就按它能进球来给。
3. **单边型别贪3:0**：马尔默、布拉格斯拉维亚都是"强队大胜"失败。一方属性强时给2:0比3:0稳。

**复盘铁律：每场复盘必须回答"为什么错——漏了什么机制"，禁止只数对错场次。**

## 经验信号优先级（按实战验证排序）

**⚠️ 样本分级声明（2026-08-13）：以下信号按样本量分三档——**
- **【数据铁证】**（2026年全量91,771场回测）：低比分51.9%、单挑1:1约11.8%——样本充足，可信
- **【假设】**（5-30场实战观察）：三条反直觉规律、单边别贪3:0——样本不足，只能"倾向"，不能断言
- **【单场观察】**（<5场）：任何"上次X命中了所以这次还X"——只参考，不作下注依据

**第一步先定比赛性格，再定比分：**

| 性格 | 识别特征 | 该给什么比分 |
|---|---|---|
| **低比分型（首选）** | 【数据铁证】大部分比赛；2026年低比分组6个选项覆盖51.9%，中比分28.6%，高比分15.5% | **1:0、1:1、2:1、0:1、0:0、2:0 优先**；单挑优先1:1/1:0 |
| **单边型** | 【假设】一方近期火+一方客场哑火 | 2:0、1:0，**别贪3:0**（【单场观察】马尔默3:0→1:2、本菲卡3:0→2:2 仅2例，作参考不作铁律） |
| **铁桶型** | 【假设】双方都闷、进球少 | 1:0、1:1、0:1 |
| ~~屠杀型~~ | **已删除**【单场观察5场中1场，样本不足但方向一致】 | 最多给2:0，不给3:0 |
| ~~对攻型~~ | **已删除**【单场观察4场0中】 | 不再因"双方都能进球"押3:2/2:3 |

**第二步再叠加这些信号（除标注外均为【假设】级，样本<30）：**
1. 客场崩盘 + 主/客队近期火 —— 给2:0、1:0，不贪大
2. 南美赛事低比分 —— 【假设】铁桶型，1:0/1:1/0:0
3. 杯赛闷局 —— 【假设】铁桶型（**例外见第5条**）
4. **比分从低比分组选，除非有极强证据才出组**（【数据铁证】2026：低比分51.9% vs 高比分15.5%）
5. **资格赛"强弱悬殊局"比分上调（【假设】n=4，2026-08-14 26084期复盘，待验证）**：
   - 识别特征：**首回合领先 ≥2球 + 主场 + 对手联赛级别低2档**（如北西兰vs冰岛瓦路尔、圣加仑vs摩尔多瓦谢里夫、中日德兰vs爱超波希米亚、安德莱赫特vs PAOK）
   - 这类局**不是"守平小胜"，而是实力碾压照样大胜**：北西兰5:0（我给2:0少3球）、圣加仑5:1（给2:1少3球）、中日德兰3:2（给1:0少2球）
   - **修正**：比分上调至 3:0 / 3:1 / 4:0 级别，不默认1:0/2:0小胜
   - ⚠️ 与"单边型别贪3:0"不矛盾：那条针对**实力不悬殊的联赛内部局**（状态火 vs 哑火）；本条针对**实力碾压的跨级别资格赛局**。判据是"联赛级别差"，不是"状态"。
6. **"守平即晋级"≠"小胜"**：领先方守平只是战意（不会全力进攻），但实力碾压时，即使收着踢也照样大胜。判断比分要看**实力差**，不看战意——战意决定"会不会翻车"，实力差决定"能赢几个"。

## 比分概率天花板（必须对用户诚实）

- 2026年真实数据：**低比分组（1:0/1:1/2:1/0:1/0:0/2:0）覆盖51.9%**，中比分28.6%，高比分（3:2/2:3/4:0等15个）仅15.5%
- 单挑单个比分：1:1最高11.8%，1:0为9.9%
- 因此：预测优先从低比分组选，单挑优先1:1/1:0，方向命中率高于精确比分
- 输出时永远带上"模型概率原始值"，不夸大

## 赛前情报收集（强制步骤，每场必做）

**来源链路（全部免费、无key）：**
1. **北单官方250接口** → 当天场次（已有）：`https://www.bjlot.com.cn/data/250ParlayGetGame_260XX.xml`
2. **Sofascore API（伤病/停赛/阵容）** — 必须用 browser_use 的 execute_js fetch 访问（curl直连403，浏览器内通）：
   - 搜队拿ID：`/api/v1/search/all?q=队名` → `results[].entity.id`
   - **赛前缺阵名单（首选，2026-08-13实测有效）**：`/api/v1/team/{id}/events/next/0` → 取近期比赛 event.id → `/api/v1/event/{event.id}/lineups` → `home/away.missingPlayers[]`，每项含 `player.name` + `description`（具体伤情：Hamstring/Knee Surgery/ACL/Thigh等）+ `reason`（枚举，1=伤病）。**比全队伤病列表精准——只列"这一场"打不了的人，含门将/核心缺阵，是判断比分的第一手依据**
   - 球队伤病（兜底/全量）：`/api/v1/team/{id}/players` → `players[].player.injury{reason, status(dayToDay/out), expectedReturn, startDate}`
   - 比赛详情：`/api/v1/event/{id}`
   - **注意**：按日期列赛事端点已废弃（scheduled-events 404），用"北单场次→逐队搜索"替代
3. **Open-Meteo 天气（免费无key）**：
   - 球队详情 `/api/v1/team/{id}` → `venue.venueCoordinates{latitude, longitude}`（球场坐标）
   - 天气：`https://api.open-meteo.com/v1/forecast?latitude=X&longitude=Y&hourly=temperature_2m,precipitation,wind_speed_10m&timezone=auto` → 取开赛时刻温度/降水/风速
4. **过程数据画像（2026-08-14 新增，死磕比分的核心升级）**：
   - **为什么要用**：预测进球该看"过程"（射门质量/重大机会），不是"历史比分频率"。前者是因果（射门多+转化高→进球多），后者是结果（命中率天花板12%）。
   - **拿什么**：`/api/v1/team/{id}/unique-tournament/{ut}/season/{sid}/statistics/overall` → statistics 字段含：
     - 进攻：`shots`(射门) `shotsOnTarget`(射正) `bigChances`(重大机会) `bigChancesCreated`(创造重大机会) `bigChancesMissed`(浪费) `goalsScored`
     - 防守：`shotsOnTargetAgainst`(被射正) `bigChancesAgainst`(被创造重大机会) `goalsConceded` `cleanSheets`
     - `matches`(场次)
   - **怎么拿 season 参数**：`/api/v1/team/{id}/events/next/0` → `event.season.id` + `event.tournament.uniqueTournament.id`
   - **计算**：`process_stats.py` 算双方期望进球（进攻系数=重大机会创造+射正率，防守系数=被创造重大机会+被射正），`save_process_data.py` 转存抓取的原始数据
   - **定位（死磕精确比分，不碰大小球）**：过程数据推导出的期望进球，**直接映射成精确比分候选**——如期望 2.57:3.89 → 候选 2:3 / 3:4，这就是精确比分预测，不是大小球。
   - **⚠️ 诚实边界**：①真 xG 免费层拿不到（shotmap 404），只有 bigChances 这个粗糙代理；②当前赛季刚开季时 statistics 端点 404，只有上赛季数据（赛季更替期要打折）；③**无法历史回测**（免费源不给历史当时的过程数据），只能前瞻实盘验证；④初版期望进球公式系数偏高（实测贝西克塔斯vs本菲卡算出3:4，偏大），**系数待实盘校准——校准目标就是让"期望进球→精确比分"的命中率提高，不是退回去看大小球**

**不可用源（别再试）：** FBref/Transfermarkt（Cloudflare/AWS WAF）、football-data.org（需key）、api-football（需注册key且免费层100次/天）、PyPI transfermarkt库（无aarch64 wheel）、FotMob（API 404 已封，2026-08-13实测）

**⚠️ 单点依赖风险（2026-08-13 调研结论，漏洞#3）：** 伤病/缺阵只有 Sofascore 一个免费源可用（FotMob/Transfermarkt/FBref 均被 WAF/封禁）。缓解措施：
1. **双端点交叉验证**：`team/{id}/players`（全队伤病）与 `event/{id}/lineups` 的 `missingPlayers`（赛前缺阵）是两条独立数据路径，同时查、互相印证，一方异常时另一方兜底
2. **多时点抓取**：预测前、临场前至少抓两次，看伤病名单是否稳定（新增/恢复）
3. **Sofascore 403 限流**：抓取间隔≥3秒，触发 403 就 navigate 刷新首页重置会话，不硬重试

**收集内容清单（每场）：**
- **赛前缺阵名单（首选）**：missingPlayers 的 name + description + reason，标注核心球员（主力/射手/门将）——这是"这一场"确定的缺阵，含停赛和伤病
- 双方伤病名单（兜底）：reason + status + expectedReturn
- 停赛/轮换：从 missingPlayers 的 reason 值区分（1=伤病，其他=停赛等），或从伤病外缺阵信号判断
- 天气：开赛时刻温度、降水概率/量、风速（大雨/大风影响进球数）
- 球场：人工草/天然草、高原（如玻利维亚）、容量气氛
- **首回合后中间比赛**（资格赛两回合必查）：首回合后各队是否又打了联赛/杯赛，胜败如何——判断体能消耗和状态拐点（例：流浪者8/9主场1:2输→状态实崩）

**情报对预测的影响：**
- 主力射手out → 该队进球期望下调
- 门将out → 该队丢球期望上调
- 大雨/大风 → 倾向低比分
- 情报缺口 → 该场置信度下调或弃选

## 预测流程（当前实际情况驱动，历史仅参考）

**主心法：每场预测 = 只回答一个问题——"这场现在到底会怎么踢？"**
依据全部来自当下：本场伤病/停赛/轮换、开赛天气、双方近期真实状态、本场战意。**不查往年统计、不套历史频率。**

**⚠️ 复盘基准铁律（2026-08-15 用户要求：准则+历次复盘经验=下次预测的基准，必须强制执行，不是参考）**：
每场预测前，逐条对照以下从历次复盘沉淀的检查项，**任何一条不满足就要停下来修正推导**：

1. **方向判断前必读本场主客场景**（8/14教训：场7/33/46主场强却判给客队）——先看"主队主场近6场"和"客队客场近6场"，再看整体状态
2. **近6场分主客场读**，禁止把客场战绩当球队状态（8/14：场2/9/11/19）
3. **首轮爆发/热身连胜≠状态**，是单场观察（8/14：场7首轮6:1、场47热身三连零封）
4. **依据里写了"防线漏/火力强"→比分敢给大**（8/14：10场方向对但进球少给；LASK近6场5场≥3球我给2:0实4:1）
5. **2:3/3:2/3:3/3:4/5:1/胜其它/负其它是正常比分**，真实30天970场2:1占10.4%、2:2占5.6%——大球属性队互碰不许给低比分（8/10：莫斯vs奥德实3:3我给1:1）
6. **伤停必须落到方向判断**，不是写进依据当摆设（8/14场53：竞技缺5人写进依据却没改方向，实际0:1输；场52把客队伤停读成客队弱，没看主队更弱）
7. **门将伤=丢球预期↑、锋线伤=进球预期↓**，直接改比分
8. **杯赛/无情报场次弃选**（8/14：意杯/爱杯/比乙4场全错或偏）
9. **样本不足（一方近6场<6场）弃选**（8/10场289：明知客队2场样本还硬出）
10. **没把握=0场**，不凑数，不许"低置信先出着"

1. 拉取官方当前期赛程（`scripts/update_history.py`）
2. 锁定当天窗口（10:00–次日10:00）销售中场次
3. **逐场收集当前情报（强制，见"赛前情报收集"节）**：Sofascore拉双方伤病/停赛名单，Open-Meteo拉开赛天气（温度/降水/风速），查球场（高原/草皮/容量）
4. **逐场拉近期真实状态**：双方各自近5-8场的比分、进球、丢球、状态趋势（上升/下滑/换帅/新赛季）——这是"当前状态"，不是历史统计。**必须分主客场记录**（主队主场近6场 / 客队客场近6场）
4.5. **对照复盘基准铁律（上面10条）**：任何一条触发反例，修正推导后才继续
5. **逐场推导剧本**（核心）：把双方当前情报+当前状态合起来，回答本场实际走向：
   - 双方实力/状态均势 + 都偏闷 + 无关键射手/门将伤 + 天气利于低比分 → **本场剧本=1:1**（这是推导，不是套概率）
   - 一方明显强/状态火 + 另一方哑火或缺核心 → **单边剧本**：2:0/1:0/2:1
   - 双方都大球属性 + 状态开放 → **对攻剧本**：2:1/2:2/3:1（**大球属性互碰敢给3:2/2:3/3:3**）
   - 关键情报（核心射手out、门将out、高原、大雨）→ 直接影响上述判断
6. **剧本→唯一比分**：按推导出的剧本给出该场真实最可能比分。**强强弱悬殊局敢给大比分（5:0/4:1/1:6），依据写了火力/防线漏就跟着放大**
7. 只选当前情报完整、剧本清晰的场次（通常3-5场，可0场）；情报缺口 → 标注或弃选
8. 存档预测快照（时间戳+双方伤病+天气+近期状态+剧本推导+比分依据）
9. **同步到GitHub公开仓库**（`longgeyyds/beidan-score-predictor`）：跑 `python3 sync_github.py "同步说明"` 自动复制快照/复盘/脚本/坐标缓存到本地镜像并 push（SSH走443端口）。预测→开奖→复盘全程公开是仓库核心卖点。**必须走脚本，不得手动复制**（手动复制曾导致镜像丢失，8/13教训）
10. 输出：场次、对阵、唯一比分、**当前情报依据**（伤病/天气/状态）、剧本推导、**估计概率 p**（必附，2026-08-13 修复"无概率"漏洞）：
    - 估计概率 = 比分概率天花板基准（1:1≈11.8%、1:0≈9.9%）± 情报修正（门将伤/核心缺阵/高原等上调或下调 2-5 个百分点）
    - 复盘按 log-loss = -ln(p_命中) 结算，基线≈2.12，**低于基线才算预测有信息量**（否则就是"命中率靠瞎猜"）
    - 禁止只给比分不给概率——没有概率的预测无法区分"运气"和"能力"
11. **历史数据角色**：仅在了解联赛风格/球队底蕴时作背景参考，绝不出现在比分推导里

## 复盘流程（每次赛后必做，生成 review_YYYYMMDD.md）

0. **复盘目的=学习并回写基准（2026-08-15用户铁律）**：复盘的每一个"为什么对/为什么错/为什么爆冷"，必须抽象成可执行规则，**回写进本SKILL的"复盘基准铁律"清单**，成为下一场预测的强制检查项。复盘不学习=白复盘，用户原话"你自己复盘的东西你都不学习，你复个毛线"。
1. 拉官方赛果，逐场对比预测vs实际，填入当日复盘档案：
   - 每场：预测/实际/方向/结果（✅精确/方向✅/❌）
   - 双轨结算：精确比分命中率（对比历史众数基线约12%）+ 方向命中率
2. **命中场次同样分析**（不是只看错场）：为什么对了？哪个信号起作用了？能否复制？**命中机制写入经验手册（lesson_handbook.md）可复制清单**
3. **机制错因分类**（为什么错，不是错几场）：
   - 数据过期（用了上赛季）→ 换新数据
   - 大球属性没查（近8场≥3球占比）→ 补查分布
   - 把大球属性队当哑火 → 大球队按它能进球给
   - 单边贪3:0 → 最多2:0
   - 交锋旧账误导 → 只参考
   - 南美铁律套死 → 对位优先
   - 纯赌无依据 → 承认
   - **方向反 → 检查是否没读本场主客场景/把客场当状态**
   - **进球少给 → 检查依据是否写了"防线漏/火力强"却没放大比分**
   - **伤停没用 → 检查伤停是否只写依据没改方向**
3.5. **逐场写因果，不是记流水账**：每一场必须回答"为什么"，指出具体漏掉的信号。禁止只列预测/实际/对错表
4. **更新累计账本** `review_ledger.md`：加一行当日数据，刷新累计命中率。**账本必须含置信度分级累计（2026-08-13强化）**：
   - 每期结算后，按 A/B/C 级分别累计：命中数 / 总场数
   - 账本固定四栏：`日期 | 期号 | 总命中率 | A级命中率(n) | B级(n) | C级(n) | 方向命中率`
   - **样本门槛**：任何一档累计 <30 场，其命中率数字**不得用于判断**，只在栏内标注"(样本不足)"
   - **滚动校准**：每满30场，输出"我标的A级命中 vs 实际A级命中"——若 A级 ≈ B级 ≈ C级，说明置信度分级无信息量，删除该维度
5. **信号验证表更新**：每个信号是保留/调整/删除，写进 ledger 的信号验证记录
6. 规则改动必须**全样本回测**验证，不因单场翻案
7. **回填预测快照的事后对照区**：预测时留的空位，赛后必须填上实际比分
8. **半年复核跨年池**（1月/7月）：凡1:1率连续3个月走低的联赛（葡甲/意甲式退化）立即剔除，替换进池必须连续两年>12%+当期实测达标
9. **校准评估（2026-08-12新增，学自 Hicruben/world-cup-2026-prediction-model，87★严谨度最高）**：
   - 预测时给每场标注**置信度等级**（A 情报全+画面清晰 / B 情报全画面一般 / C 有缺口），复盘时统计各级别实际命中率
   - **置信度校准表**：每10期复盘一次，输出"我说A级多准 vs 实际多准"——若A级命中率≈B级，说明置信度判断没信息量，必须调整
   - **log-loss 计算**（可选但推荐）：预测给唯一比分时附带信心概率 p（如1:1给12%、2:1给10%），复盘时 log-loss = -ln(p_实际命中场) 或 -ln(1-p_错场)。基线 log-loss ≈ -ln(0.12) ≈ 2.12，**低于2.12说明预测优于无脑众数**。只用准确率会奖励瞎猜，log-loss 惩罚过度自信
   - 目的：验证"选场能力"是否真实存在——命中率略高可能只是运气，log-loss+校准表能区分运气与能力

## 校准评估（2026-08-12 从 GitHub 生态学习，实测验证后采纳）

**来源**：Hicruben/world-cup-2026-prediction-model（87★，GitHub 足球预测方法学最严谨项目）用 RPS/log-loss/Brier 评估模型，明确"准确率奖励瞎猜"。

**北单版落地（只取适合精确比分赛道的部分）：**

1. **置信度校准表（每10期复盘刷新）**：
   | 置信度 | 预测时含义 | 复盘统计 |
   |---|---|---|
   | A级 | 情报全（伤病/天气/状态都查到）+ 剧本清晰 | 实际命中率应 > B级 |
   | B级 | 情报全但剧本一般 / 有1项缺口 | 实际命中率居中 |
   | C级 | 情报缺口 ≥2项 | 实际命中率应最低，若反超A级则置信度体系失效 |

2. **log-loss 附置信度**：预测输出时给唯一比分附估计概率 p（来自"比分概率天花板"基准±情报修正），复盘用 `log_loss.py` 结算。**注意（2026-08-13 修正早前错误表述）**：平均 log-loss 基线是 **0.367**（无脑1:1 p=12%），不是 2.12——2.12 是"命中那场"的单场值，不是平均值。判断：平均 log-loss < 0.367 且 p均值≈实际命中率（校准偏差<5%）才算概率预测有信息量。**log-loss 惩罚过度自信**：p 估大了但没中，log-loss 会变差。

3. **规则**：不达标就承认——若A级连续20期命中率≈B级，说明"选场能力"是幻觉，删除置信度分级，回归纯画面分析。

**已验证排除项（2026-08-12 实测证伪，不再重复劳动）：**

- **Dixon-Coles 双变量泊松 + Elo**（学自 Hicruben）：移植到北单91,771场全量数据 walk-forward 实测 → 精确比分命中 **12.09%**（n=17,097），低于跨年池+大球过滤基线 **13.25%**；Top1 输出 89.7% 退化成"无脑1:1"；方向命中 30.2% 远低于猜主胜43%基线。**结论：Dixon-Coles 是胜负概率模型（对方向有效），不适用于25选1的精确比分赛道，不采用。** 实测脚本 /tmp/learn/backtest_dc_beidan.py，报告已存入仓库 docs/backtest_dc_report.md

## 禁区

- 禁止说"方向命中率高所以预测准"——用户买的是比分
- 禁止拿"我觉得稳"当信心——置信度必须来自数据画面
- 禁止用历史场均进球推当天（状态会波动）
- 禁止为凑数强选
- 禁止声称命中率超过验证过的基线
- **比分以实际推导为主，SP辅助预测，不追高SP（2026-08-14用户澄清）**：**不存在"梦幻场"分类**，不因SP高去搏某个比分。比分 = 情报+状态+战意+实力差 推导出的实际最可能比分——推导出来是大比分（如强弱悬殊局 5:0/3:2）就给大比分，即使 SP 高；推导出来是 1:1 就给 1:1，即使 SP 低。**但SP作为辅助预测信息必须用**：官方25比分SP去水=市场先验，用于校准推导、交叉验证、风险提示（2026-08-14教训：误执行成完全不看SP，54场11.1%≈瞎猜）。亏损根因从来不是"SP 高"，而是"比分猜不准"；但把市场信息扔掉是自废先验，同样导致猜不准。
- **禁止虚假宣传（2026-08-12写入）**：对外文案（README/docs）只能基于已验证数字，禁止声称"85.9%准确率"式无验证数字——GitHub上这类项目（如w5-football-prediction 20★）恰是反面教材，懂行的人一眼看穿，吹牛=丢人。吸引人才靠"透明可审计"的诚实定位，不靠虚假数字
- 禁止用SP绝对值作为选场、过滤或排序依据（**SP>5规则已取消**）；SP流向仅辅助验证，不单独决定候选
